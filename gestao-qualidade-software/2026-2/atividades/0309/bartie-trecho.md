# Trecho para ler *antes* da Aula 03

**Livro:** Alexandre Bartie, *Garantia da Qualidade de Software*.  
**Trecho:** § 3.2.3 — Definição comum de testes.  
**Origem:** transcrição no flask-dashboard (PDF p. 38). Ortografia regularizada; sem inventar frases.

---

De forma geral, todas as equipes de desenvolvimento aplicam testes em seus softwares, independentemente de os testes serem bem planejados, bem estruturados e de como são executados. O fato é que esses testes não são suficientes para detectar os erros que estão inseridos dentro de uma aplicação.

Um dos motivos básicos para que isso ocorra é a forma com que esses profissionais encaram os testes de software. Todos enxergam os testes como uma forma de provar que tudo está bem e funcionando conforme o estabelecido. O entendimento sobre testes é sempre colocado sobre o prisma de avaliar se tudo está funcionando adequadamente.

O fato é que é mais fácil provar que “algo funciona” do que provar que “algo não funciona”, o que significa que teremos um menor esforço em provar o funcionamento de um software do que o contrário.
