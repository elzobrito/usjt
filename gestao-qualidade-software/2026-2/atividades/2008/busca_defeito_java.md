# Caça aos defeitos — Java

O desenvolvedor afirma:

> “O programa compilava ontem e estava funcionando”.

Analise o código e encontre o maior número possível de problemas.

## Para cada problema encontrado, indique:

1. Onde está o problema;
2. Se é um erro de **compilação, execução ou lógica**;
3. O que poderá acontecer;
4. Como você corrigiria;
5. Se um teste poderia detectar o problema.

## Observação

Esse exemplo tem erros de naturezas diferentes. Há problemas que impedem a compilação, um que pode provocar exceção em execução e outros em que o programa pode executar, mas produzir comportamento incorreto.

Isso é particularmente interessante para a aula de qualidade porque permite fazer a pergunta:

> **Se o programa compilar, significa que ele tem qualidade?**

E depois:

> **Se executar sem lançar nenhuma exceção, significa que está correto?**

## Orientação ao professor

Não informe inicialmente aos alunos quantos erros existem. Isso evita que parem de procurar quando atingirem um número predeterminado.
